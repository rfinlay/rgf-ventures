Questions you will get, Part A

  • "Did you build all of that in a day?" The spine module, yes, from his template; it was tested end to end against the two sample reports he sent, and reviewed by an independent code reviewer before release. The calcium and thyroid modules came first, over the summer.
  • "Where does the data go?" Nowhere. The browser assembles the report; only a temporary draft lives on that computer for four hours. No patient data is stored on a server. Sign-ins are recorded.
  • "Is it FDA cleared?" It is not a device and does not diagnose; it formats what the radiologist graded, from his own template, and he signs. Reading the images would be a different product with a regulatory path.
  • "Can it read the MRI for him?" Not today, and not promised. That is diagnostic software. It is a future item with a regulatory path.
  • "What about Spanish?" Click Español above the preview: the same report, drafted in Spanish, flagged as pending his review.
  • "Can other radiologists use it?" Yes; the templates are per radiologist. Keep licensing to other centers out of this room (private conversation with Luis).

The prior authorization agent (about 3 minutes)

Works on laptop, iPad, phone. No login. Open it before dinner and leave the tab up. Source and full notes: github.com/rfinlay/imaging-priorauth-demo

What is real and what is simulated

PieceStatusWhat to say if asked
Payer submissionREALA Da Vinci PAS FHIR bundle is POSTed to HL7's public prior-auth reference server, which validates and stores it and returns a real tracking number.
Reading it backREALA GET against the same server returns the stored record; the link opens it.
Request formatREALThe national PAS standard CMS requires of Medicare Advantage, Medicaid, CHIP and exchange plans by 2027-01-01.
7-day / 72-hour clocksREAL logicCMS deadlines computed from submission; the demo clock fast-forwards time.
Incoming RIS orderSIMULATEDA synthetic HL7 v2 ORM message. No live RIS is connected.
Approve / deny decisionSIMULATEDThe test server has no imaging rules, so decisions come from a scripted payer, labeled orange.
Appeal letterTEMPLATEDDrafted from the denial and the notes; a physician edits and signs. In production, a model drafts it under a BAA.
Monday reportSYNTHETICPlaceholder numbers. Theirs come from their own volume.

Two purple Human approves gates: approving the packet before it goes out, and signing the appeal. All patient data is synthetic.

Before you start, glance at the top banner. It should read "Payer sandbox: LIVE (HL7 Da Vinci PAS)" in green. If it is orange ("sandbox offline"), the demo still runs end to end; the submission just goes to the simulated payer and says so. Either way, say the line in step 4 that matches.

Watch the log fill in. Wait for the line "Payer sandbox accepted the request (HTTP 201). Tracking number …"

"That just went over the wire to HL7's prior-authorization test server, in the FHIR format CMS is requiring every Medicare Advantage and exchange plan to support by January 2027. That tracking number is real; the link opens the stored record on their server."

If Jesse wants proof, click Show the FHIR request we sent or the Open the stored response link. If the banner was orange, say instead: "Tonight the public test server is down, so this one went to our simulated payer, which is why it is labeled that way. The code path is the same."

Dr. Ortega reads it, edits it if he wants, and signs. The doctor owns the clinical argument; the agent owns the paperwork."

Questions you will get

  • "Is any of this connected to a real insurance company?" No. It talks to HL7's public test server for the prior-auth standard. Connecting to Blue Cross or UHC means credentialing with each payer, which is build work (milestone B2 onward) once the center has payer contracts.
  • "What about the clearinghouse / Availity?" Same code path; the agent can submit through a clearinghouse where a payer is not yet on FHIR. Fax-and-portal payers get a human-assisted path with the agent preparing the packet.
  • "Exa says they are building this." Good, use it if it ships and it is good. The agent sits above the PACS and RIS, so it works with Exa, Sectra, or whatever the center buys, and it covers the owner's reporting and the appeal drafting, which a PACS vendor will not.
  • "Can it get this wrong?" Yes, which is why the two purple gates exist. It never submits or signs on its own.
  • "How long did this take to build?" The prototype took an evening against a public test server. Production is the work on the build page: your RIS, your real payers, security and the BAAs, and your staff testing it before you open.
